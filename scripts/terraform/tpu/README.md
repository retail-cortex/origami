# Cloud TPU v5e GKE Provisioning & vLLM Deployment Guide

This directory provisions a single-node Google Kubernetes Engine (GKE) cluster equipped with Cloud TPU v5e accelerators (`ct5lp-hightpu-4t`, 4 chips / 64GB HBM) and deploys the vLLM TPU inference server.

---

## 1. Pre-Creation Requirements & Configuration

### Prerequisites
- **Terraform**: `>= 1.5.0`
- **Google Cloud CLI (`gcloud`)**: Installed and configured.
- **kubectl**: Installed for Kubernetes cluster interaction.

### Step 1: Authenticate Local Environment
Establish active `gcloud` user credentials and Application Default Credentials (ADC):

```bash
gcloud auth login
gcloud auth application-default login
```

### Step 2: Configure GCP Project Target
Set the active project to match `var.project_id` (`cs-poc-gvosjaln9q6gcudiayjqdzq`):

```bash
gcloud config set project cs-poc-gvosjaln9q6gcudiayjqdzq
```

### Step 3: Enable Cloud Services
Activate Compute Engine, Kubernetes Engine, and Cloud TPU APIs:

```bash
gcloud services enable compute.googleapis.com container.googleapis.com tpu.googleapis.com
```

### Step 4: Configure Input Variables
Review default configuration parameters in [variables.tf](file:///Users/rmcguinness/Projects/rrmcguinness/origami-ai-router/scripts/terraform/tpu/variables.tf) and variable overrides in [terraform.tfvars](file:///Users/rmcguinness/Projects/rrmcguinness/origami-ai-router/scripts/terraform/tpu/terraform.tfvars):

| Parameter | Default Value | Description |
|---|---|---|
| `project_id` | `cs-poc-gvosjaln9q6gcudiayjqdzq` | Target GCP Project ID |
| `region` | `us-central1` | Primary GCP Region |
| `zone` | `us-central1-a` | Target GCP Zone supporting Cloud TPU v5e |
| `cluster_name` | `origami-tpu-gke` | GKE TPU Cluster Name |
| `machine_type` | `ct5lp-hightpu-4t` | GCP Machine Type (4x TPU v5e chips) |
| `tpu_model` | `google/gemma-4-12B-it-qat-q4_0-unquantized` | Target model deployed to vLLM |
| `hf_token` | `""` | Optional Hugging Face Token for gated repositories |

## 2. Terraform Execution Workflow

### Step 1: Initialize Provider Plugins
Download provider binaries (`hashicorp/google` and `hashicorp/kubernetes`):

```bash
terraform init
```

### Step 2: Lint and Validate Configuration
Validate structural syntax and HCL formatting:

```bash
terraform fmt -check
terraform validate
```

### Step 3: Generate Execution Plan
Preview resource additions:

```bash
terraform plan
```

### Step 4: Apply Infrastructure Provisioning
Provision VPC network, subnets, GKE TPU cluster, TPU node pool, model bucket, and Kubernetes workloads:

```bash
terraform apply
```

To supply a Hugging Face user token during apply:

```bash
terraform apply -var="hf_token=hf_xxxxxxxxxxxxxxxxxxxx"
```

## 3. Post-Creation Operational Steps

### Step 1: Register GKE Credentials
Execute the output command generated by Terraform to register cluster credentials in `kubectl`:

```bash
gcloud container clusters get-credentials origami-tpu-gke --zone us-central1-a --project cs-poc-gvosjaln9q6gcudiayjqdzq
```

### Step 2: Upload Models to Google Cloud Storage
Bucket output name: `cs-poc-gvosjaln9q6gcudiayjqdzq-tpu-vllm-models` (mounted via GCS Fuse to `/models` inside the vLLM container).

To sync your locally fetched models from the project root `models/` directory to the GCS bucket:

```bash
# Sync entire local models/ directory to the GCS bucket
gcloud storage rsync -r ../../../models/ gs://$(terraform output -raw gcs_model_bucket)/

# Alternatively, copy a specific model directory
gcloud storage cp -r ../../../models/gemma-4-12B-it-qat-q4_0-unquantized gs://$(terraform output -raw gcs_model_bucket)/
```

### Step 3: Verify TPU Workloads & Node Status
Check namespace, pod status, node labels, and container logs:

```bash
# Verify node pool status
kubectl get nodes -l cloud.google.com/gke-tpu-accelerator=tpu-v5-lite-podslice

# Verify TPU vLLM pod status
kubectl get pods -n tpu-serving -o wide

# Inspect deployment details
kubectl describe pod -n tpu-serving -l app=tpu-serving-router

# Stream vLLM container logs
kubectl logs -n tpu-serving -l app=tpu-serving-router -f
```

### Step 4: Inspect Service Endpoint & Send Inference Request
Retrieve the external LoadBalancer IP assigned to the TPU service:

```bash
EXTERNAL_IP=$(kubectl get svc -n tpu-serving tpu-router-service -o jsonpath='{.status.loadBalancer.ingress[0].ip}')
echo "TPU Service LoadBalancer IP: ${EXTERNAL_IP}"
```

Issue a test completion request against the OpenAI-compatible vLLM endpoint:

```bash
curl http://${EXTERNAL_IP}:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "google/gemma-4-12B-it-qat-q4_0-unquantized",
    "messages": [{"role": "user", "content": "Ping"}]
  }'
```

## 4. Resource Teardown

To destroy the GKE cluster, node pools, bucket resources, and services to prevent ongoing cloud resource charges:

```bash
terraform destroy
```
